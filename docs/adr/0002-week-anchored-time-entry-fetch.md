# Fetching TimeEntrySet pages one week at a time, not via a date-range $filter

`Z_ONETIME_SRV`'s `TimeEntrySet` doesn't support arbitrary OData `$filter` — confirmed by testing: a `$filter` on `StartDate ge ...` and `startswith(text, ...)` was silently ignored, returning an unrelated ~2-day window regardless of what was asked for. The real Fiori app (`ZONETIME5`) instead requests one week at a time via `$filter=StartDate eq datetime'<mondayOfThatWeek>T12:00:00' and EmployeeNumber eq '<emp>' and Mode eq 'WEEK'` — an equality match on a fixed weekly anchor, not a range. `handleFetchToBeModified` in `background.js` walks backward week-by-week from the current week to cover the [[TO_BE_MODIFIED entry]] lookback window, merging and filtering client-side, because there is no server-side way to ask for an arbitrary date range in one call.
